# راهنمای بکاپ و بازیابی

## خلاصه سیاست (بخش ۱۷ سند)

| مورد | پیاده‌سازی |
|---|---|
| بکاپ روزانه PostgreSQL | `pg_dump` با فرمت custom، هر شب ساعت ۰۴:۰۰ به وقت تهران (`basharnia-backup.timer`) |
| بکاپ فایل‌ها | کل `/data/basharnia` (عکس‌ها، PDFها، لوگو)، بدون صوت موقت |
| نگهداری | ۷ نسخه روزانه و ۴ نسخه هفتگی (جمعه)، هم روی سرور و هم در مقصد خارجی |
| نسخه خارج از VPS | با `rclone` به هر سرویس پشتیبانی‌شده؛ پس از ارسال، sha256 فایل مقصد با فایل محلی مقایسه می‌شود |
| رمزگذاری | **همه** بکاپ‌ها (محلی و خارجی) با `age` رمز می‌شوند. فقط **کلید عمومی** روی سرور است، پس حتی با نفوذ به سرور، بکاپ‌ها قابل خواندن نیستند |
| بررسی سلامت | `pg_restore --list` روی dump، و فایل MANIFEST شامل sha256 هر جزء، تعداد ردیف‌ها و نسخه schema |
| اطلاع خطا | اگر بکاپ ناموفق شود، پیام تلگرام برای مربی فرستاده می‌شود (با همان ربات) |
| تمرین بازیابی | `restore-drill.sh` بکاپ را در یک دیتابیس و پوشه جداگانه بازیابی و با سیستم زنده مقایسه می‌کند؛ به سیستم زنده دست نمی‌زند |

> **کلید خصوصی (`basharnia-backup.key`) را گم نکنید.** بدون آن هیچ بکاپی قابل بازیابی نیست. دو نسخه در دو جای امن نگه دارید (مثلاً مدیر رمز عبور و یک USB). این کلید هرگز نباید روی سرور بماند.

## مقصد خارجی و هزینه

حجم داده یک مربی کم است (معمولاً زیر ۱ گیگابایت، که بیشترش عکس است). گزینه‌های مناسب در زمان نگارش (**شرایط و قیمت را هنگام راه‌اندازی بررسی کنید**):

| گزینه | هزینه تقریبی | توضیح |
|---|---|---|
| Backblaze B2 | ۱۰ گیگابایت اول رایگان | سازگار با S3 و rclone |
| Cloudflare R2 | ۱۰ گیگابایت در ماه رایگان | بدون هزینه خروج داده |
| Google Drive | ۱۵ گیگابایت رایگان (مشترک با Gmail) | rclone پشتیبانی می‌کند؛ برای حجم کم کافی است |
| Hetzner Storage Box | حدود ۳ تا ۴ یورو در ماه | پولی؛ اگر VPS هم در Hetzner است ساده است (SFTP) |
| یک کامپیوتر یا سرور دیگر | — | از طریق SFTP با rclone |

سرویس‌های رایگان ممکن است برای کاربران ایرانی یا روش پرداخت در دسترس نباشند. اگر هیچ گزینه رایگان قابل اتکایی ممکن نبود، طبق سند باید هزینه یک گزینه پولی را پذیرفت؛ **بکاپ خارجی حذف‌شدنی نیست.**

برای تعریف مقصد (مثلاً B2) روی سرور:

```bash
sudo rclone config
```

بعد در `/etc/basharnia/backup.env`، مقدار `RCLONE_REMOTE=<نام-remote>:basharnia-backups` را بگذارید.

## اجرای دستی و بررسی

```bash
sudo systemctl start basharnia-backup.service && journalctl -u basharnia-backup -n 40
```

```bash
sudo ls -lh /var/backups/basharnia/daily /var/backups/basharnia/weekly
```

```bash
systemctl list-timers basharnia-backup.timer
```

## تمرین بازیابی (ماهانه، و حتماً پیش از تحویل)

کلید خصوصی را موقتاً به سرور منتقل کنید. **روی کامپیوتر خودتان:**

```bash
scp basharnia-backup.key coachadmin@SERVER:/tmp/drill.key
```

روی سرور:

```bash
sudo /opt/basharnia/infra/backup/restore-drill.sh --key /tmp/drill.key
```

```bash
shred -u /tmp/drill.key
```

خروجی موفق شبیه این است: `restore drill PASSED: 18 tables and N files identical to live`. اگر بعد از بکاپ داده‌ای تغییر کرده باشد، اسکریپت تفاوت‌ها را نشان می‌دهد و با کد ۲ خارج می‌شود؛ در این حالت بکاپ سالم است ولی کهنه‌تر از داده فعلی است.

## بازیابی واقعی

### الف) خرابی داده روی همان سرور

```bash
sudo /opt/basharnia/infra/backup/restore.sh --key /tmp/drill.key --latest
```

این دستور:
1. بکاپ را رمزگشایی و **sha256 همه اجزا** را بررسی می‌کند (فایل آسیب‌دیده یا کلید اشتباه رد می‌شود).
2. خلاصه MANIFEST را نشان می‌دهد و برای ادامه، تایپ عبارت `restore` را می‌خواهد.
3. `api` و `worker` را متوقف می‌کند، دیتابیس را از نو می‌سازد و dump را برمی‌گرداند.
4. پوشه فایل‌ها را **پاک نمی‌کند**؛ آن را به `/data/basharnia.before-restore-<زمان>` منتقل و سپس بازیابی می‌کند.
5. migrationها و سرویس‌ها را دوباره اجرا می‌کند.

برای بازیابی یک نسخه مشخص، به‌جای `--latest` مسیر فایل را بدهید (مثلاً `/var/backups/basharnia/weekly/basharnia-20261030T003000Z.tar.age`).

### ب) از دست رفتن کامل سرور

1. سرور جدید را طبق `DEPLOYMENT.md` بخش‌های ۱ تا ۴ آماده کنید. همان `.env` قبلی را استفاده کنید؛ اگر در دسترس نیست، `.env` جدید بسازید (رمز دیتابیس جدید مشکلی ندارد).
2. rclone را با همان مقصد تنظیم کنید و فهرست بکاپ‌ها را ببینید:

```bash
sudo rclone lsf offsite:basharnia-backups/daily
```

3. مستقیماً از مقصد خارجی بازیابی کنید:

```bash
sudo /opt/basharnia/infra/backup/restore.sh --key /tmp/drill.key offsite:basharnia-backups/daily/basharnia-<زمان>.tar.age
```

4. Webhook تلگرام و DNS را دوباره تنظیم کنید (`DEPLOYMENT.md` بخش‌های ۳ و ۶) و کلید را با `shred -u` پاک کنید.

## آنچه در بکاپ نیست

- **مدل Whisper**: دوباره دانلود می‌شود (`download-whisper-model`).
- **فایل‌های صوتی خام**: طبق سیاست نگهداری بعد از پردازش حذف می‌شوند؛ متن خام در دیتابیس هست.
- **`.env` و گواهی SSL**: `.env` را جداگانه و امن نگه دارید (حاوی Secretهاست)؛ گواهی دوباره صادر می‌شود.

## آزمون‌های خودکار این اسکریپت‌ها

- `infra/tests/test-backup-restore.sh`: چرخه کامل بکاپ، رمزگذاری و بازیابی روی PostgreSQL محلی، با مقصد خارجی شبیه‌سازی‌شده. موارد بررسی: رمز بودن فایل، نبودن متن خوانا، نسخه روزانه و هفتگی خارجی، sha256، نگهداری ۷/۴، رد کلید اشتباه و فایل آسیب‌دیده، تمرین بازیابی، و بازیابی مستقیم از مقصد خارجی.
- `infra/tests/test-compose-stack.sh`: کل Stack تولیدی در Docker، شامل `backup.sh` و `restore-drill.sh` در حالت compose.
