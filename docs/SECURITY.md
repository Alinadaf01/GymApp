# امنیت — Basharnia Coach CRM

این سند خلاصه کنترل‌های امنیتی پیاده‌شده (بخش‌های ۱۱، ۱۵ و ۱۶ سند)، نتیجه بازبینی امنیتی فاز ۷ و کارهای دوره‌ای را نشان می‌دهد.

## سطح حمله

| ورودی | محافظت |
|---|---|
| `https://coach.example.com` (nginx، تنها سرویس با پورت عمومی؛ پنل در `/` و API در `/api`) | TLS 1.2/1.3، HSTS، هدرهای امنیتی، محدودیت حجم، rate limit، و 404 برای مسیرهای غیر API |
| `/api/*` | همه مسیرها جز health، login و webhook به **نشست** نیاز دارند (تست خودکار روی همه ۵۹ مسیر) |
| `/api/telegram/webhook` | Secret token (مقایسه زمان‌ثابت) + فقط IPهای تلگرام در nginx + فقط شناسه عددی مربی و فقط چت خصوصی |
| پنل (کانتینر Next.js، بدون پورت عمومی) | هیچ Secretی در Frontend نیست؛ CSP فقط `'self'` (API روی همان دامنه)؛ کاربر غیر root |
| SSH | فقط با کلید، بدون root، Fail2ban، UFW |
| PostgreSQL و API داخلی | بدون پورت عمومی؛ فقط در شبکه داخلی Docker (تست‌شده) |

## کنترل‌ها

**احراز هویت و نشست**
- یک حساب مدیر که با CLI ساخته می‌شود؛ رمز پیش‌فرض وجود ندارد. رمز با **Argon2id** هش می‌شود و حداقل ۱۰ کاراکتر است.
- نشست سمت سرور؛ Cookie از نوع `HttpOnly` و `SameSite=Lax` است و در production `Secure` با پیشوند `__Host-` دارد. فقط SHA-256 توکن ذخیره می‌شود.
- خروج و تغییر رمز، نشست‌ها را در سرور باطل می‌کند. توکن در localStorage نگهداری نمی‌شود.
- **محدودیت ورود**: ۵ تلاش برای هر نام کاربری و ۲۰ تلاش برای هر IP در ۱۵ دقیقه (ماندگار در DB)، به‌علاوه `limit_req` در nginx.
- **CSRF**: درخواست‌های تغییر‌دهنده هدر `X-Requested-With` می‌خواهند و Origin، اگر فرستاده شود، باید دامنه پنل باشد. CORS فقط دامنه پنل را مجاز می‌کند.

**داده و فایل**
- اعتبارسنجی همه ورودی‌ها با Pydantic؛ کوئری‌ها با ORM و پارامتری؛ escape کاراکترهای `%` و `_` در جستجو.
- تصاویر: بررسی پسوند، MIME و محتوای واقعی فایل؛ ذخیره دوباره به JPEG (**حذف EXIF و GPS**)؛ نام تصادفی ۲۵۶ بیتی؛ مجوز فایل `640`؛ جلوگیری از path traversal؛ ارائه فقط پس از احراز هویت با `Cache-Control: private`؛ حذف رکورد فایل را هم حذف می‌کند.
- رضایت شاگرد برای تصاویر ثبت می‌شود (`photo_consent_at`).
- PDF: HTML با autoescape؛ Chromium با **همه درخواست‌های شبکه مسدود**؛ دانلود فقط با نشست و `no-store`.
- صوت خام بلافاصله پس از پردازش حذف می‌شود.
- پیام‌های خطا جزئیات داخلی (traceback یا SQL) را نشان نمی‌دهند (تست‌شده). مستندات OpenAPI در production غیرفعال است.

**پیکربندی**
- Secretها فقط در `.env` (با مجوز `600`) و Environment هستند. API در production با کلید کوتاه، `DATABASE_URL` توسعه یا `FRONTEND_URL` غیر https **اجرا نمی‌شود**.
- کانتینرهای API و worker با کاربر غیر root (uid 10001) اجرا می‌شوند. لاگ کانتینرها محدود است.

**بکاپ**
- رمزگذاری با age و نگهداری **فقط کلید عمومی** روی سرور؛ نسخه خارج از سرور؛ بررسی sha256 و تمرین بازیابی (`BACKUP_RESTORE.md`).

## بازبینی امنیتی فاز ۷ — یافته‌ها

| # | یافته | شدت | وضعیت |
|---|---|---|---|
| ۱ | nginx هدر `X-Forwarded-For` ارسالی کلاینت را نگه می‌داشت و IP واقعی را به انتهای آن اضافه می‌کرد. Uvicorn (با trust به `*`) مقدار جعلی کلاینت را برمی‌داشت، پس **محدودیت ورود بر اساس IP دور زده می‌شد** (محدودیت نام کاربری همچنان کار می‌کرد) | متوسط | ✅ رفع شد: nginx هدر را با `$remote_addr` بازنویسی می‌کند (تست واقعی با nginx) |
| ۲ | Webhook تلگرام از هر IP قابل فراخوانی بود (فقط با secret محافظت می‌شد) | کم | ✅ محدود به شبکه‌های تلگرام در nginx (دفاع لایه‌ای) |
| ۳ | پیش‌فرض‌های توسعه (`DATABASE_URL` محلی، `FRONTEND_URL` با http) در production رد نمی‌شدند | کم | ✅ بررسی هنگام شروع + تست |
| ۴ | پنل هدر CSP و ضد clickjacking نداشت و هدر `X-Powered-By` داشت | کم | ✅ CSP و `X-Frame-Options` و … اضافه شد؛ بدون هیچ خطای CSP در ۳۱ صفحه (E2E) |
| ۵ | nginx: CSP، `Permissions-Policy` و rate limit عمومی API نداشت | کم | ✅ اضافه شد |
| ۶ | `pip-audit` (وابستگی‌های Python) | — | ✅ آسیب‌پذیری شناخته‌شده‌ای نیست |
| ۷ | `npm audit --omit=dev` | — | ✅ آسیب‌پذیری‌ای نیست |
| ۸ | جستجوی Secret در **کل تاریخچه Git** (توکن تلگرام، کلید خصوصی، کلید age، AWS، GitHub) | — | ✅ چیزی پیدا نشد؛ فایل `.env` یا کلیدی در مخزن نیست |
| ۹ | همه ۵۹ مسیر غیرعمومی بدون نشست 401 برمی‌گردانند | — | ✅ تست خودکار `tests/test_security.py` (فهرست مسیرها از OpenAPI استخراج می‌شود تا مسیر جدید از قلم نیفتد) |

## محدودیت‌های شناخته‌شده و تصمیم‌ها

- **CSP پنل** `'unsafe-inline'` را برای script دارد. استفاده از nonce کل صفحات را dynamic می‌کند (طبق مستندات Next.js)؛ با توجه به اینکه پنل یک کاربر دارد و همه داده‌ها با React escape می‌شوند، این مصالحه پذیرفته شد. منابع خارجی script همچنان مسدودند.
- **احراز هویت دومرحله‌ای** در محدوده نسخه اول نیست؛ رمز قوی و rate limit جایگزین آن هستند.
